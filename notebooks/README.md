# notebooks

データを調べる（EDA）ためのノートブックを置く場所。開き方（カーネルの選び方）はリポジトリ直下の README の「ノートブック」を参照。

## 最初の EDA（担当を決めて埋める）

改善を始める前に、全員でデータの姿をつかむ。1 つのノートブックを 1 人が担当し、問いに答えていく。

| ノートブック | 内容 | このノートブックで決めること |
|---|---|---|
| `eda_1_distribution.ipynb` | 価格の分布 | 外れ値を除くか、価格を対数にして予測するのが妥当か |
| `eda_2_trend.ipynb` | 価格の推移 | 時間トレンドへの対処が必要か |
| `eda_3_relations.ipynb` | 価格と各列の関係 | どんな特徴量を足すとよさそうか |
| `eda_4_train_test.ipynb` | train と test の違い | test に合わせて学習データの重みを変える必要があるか |

各ノートブックには、データの読み込みと、問いごとのヒントのコードを用意してある。

### 進め方

1. 担当するノートブックの「担当」に名前を書く
2. 問いごとにグラフや集計を作り、「分かったこと」に 1〜2 行で結論を書く
3. 「まとめ」に結論と次にやること（実験の候補）を書く
4. 出力（グラフ）を残したままコミットし、PR を出す。結論は Issue にも転記する

## ルール

- **他の人のノートブックは編集しない**。ノートブックは git で衝突すると直すのが大変なため
- 新しく調べたいことができたら、`<名前>_<テーマ>.ipynb`（例：`fujise_outliers.ipynb`）で新しいノートブックを作る
- 出力（グラフ）は残したままコミットする。GitHub 上でグラフが見られる
- 分かったことは Issue に書く。ノートブックは後から読まれにくいため
- ノートブックは調べる場所。モデルで使う処理は、ノートブックではなくモデルのコードに書いて PR を出す

## eda_utils.py

ノートブックで共通に使う処理。

```python
from eda_utils import TARGET, load, setup_plot

setup_plot()  # グラフで日本語が表示されるようにする
train, test = load()  # データを読み込み、時期・面積_数値・築年数・㎡単価などの列を足す
```

`load()` の変換は、EDA で見やすくするためのもの。モデルの前処理とは別。
