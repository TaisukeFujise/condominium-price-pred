# 精度改善のワークフロー

学習から予測までの流れと、各工程で精度改善のために打てる手をまとめる。担当を決めるときや、進捗を確認するときの地図として使う。

## 全体の流れ

工程の番号は、`main.py` で実行される順番。

```mermaid
flowchart TD
    S0["0. データ理解（EDA）<br>分布・トレンド・train と test の違い"]
    S1["1. 前処理<br>文字列 → 数値、欠損、表記ゆれ"]
    S2["2. 特徴量エンジニアリング<br>新しい列を作る"]
    S3["3. 学習データの選択<br>どの行を・どの重みで学習に使うか"]
    S4["4. 目的変数の設計<br>何を予測させるか"]
    S5["5. モデルの選択<br>アルゴリズムと損失関数"]
    S6["6. ハイパーパラメータ調整"]
    S7["7. アンサンブル<br>複数モデルの予測を混ぜる"]
    S8["8. 後処理<br>予測値の補正"]
    SUB["提出・最終提出の選択"]

    S0 -.-> S1
    S1 --> S2 --> S3 --> S4 --> S5 --> S6 --> S7 --> S8 --> SUB
```

1〜8 のどの変更も、検証（時系列 CV）のスコアで良し悪しを判定する。検証は改善の対象ではなく、固定して使う物差し（`docs/validation.md`）。

## 工程ごとの打ち手

期待度は、このコンペの性質から見たチームの見立て。実験の結果で更新する。

| # | 工程 | 打ち手の例 | 期待度 | ファイル |
|---|---|---|---|---|
| 0 | データ理解 | 四半期ごとの価格推移、価格情報区分（取引価格 / 成約価格）ごとの価格差、train と test の分布の違い | — | `notebooks/`（未作成） |
| 1 | 前処理 | 「戦前」「30分～60分」などの置き換え値の見直し、全角の統一、駅名の括弧表記の統一 | 小 | `src/preprocess.py` |
| 2 | 特徴量 | **場所**：地区・駅ごとの㎡単価（target encoding）<br>**物件**：間取りの分解（部屋数・LDK の有無）、容積率×面積<br>**集約**：駅・地区ごとの取引件数や平均築年数<br>**外部データ**：駅の乗降客数など（規約の範囲内） | 大 | `src/features/` |
| 3 | 学習データの選択 | 古い期間を捨てる・重みを下げる。外れ値（特殊な事情の取引、極端な価格）を除く。test に多い成約価格情報を重く見る | 中 | `src/selection.py` |
| 4 | 目的変数 | ㎡単価を予測して面積を掛け戻す。時間トレンドを引いてから学習し、予測時に足し戻す | **大** | `src/target.py` |
| 5 | モデルの選択 | CatBoost（カテゴリに強い）、XGBoost、ニューラルネット。損失関数を外れ値に強い Huber にする | 中 | `src/models/` |
| 6 | ハイパーパラメータ | learning_rate、num_leaves、min_data_in_leaf、正則化、feature_fraction。Optuna で探索 | 小〜中 | `src/models/params.py` |
| 7 | アンサンブル | seed を変えたモデルの平均、異なるモデルの加重平均、stacking | 中 | `src/ensemble.py` |
| 8 | 後処理 | test の時期に合わせた価格水準の補正（トレンドの延長分を掛ける） | 中 | `src/postprocess.py` |

工程 3〜8 は、CV の fold ごとに、その fold の学習データだけを使って実行される。そのため、ここで学習データから何かを計算しても（トレンドの推定など）、検証期間の情報は漏れない。

### サンプルの重み（工程 3）

学習のときに、行ごとに「どれだけ重視するか」を数値で指定するもの。モデルは各行の誤差に重みを掛けてから合計し、それを小さくするように学習する。重み 2 の行は同じ行を 2 回入れたのとほぼ同じ扱いで、重み 0 の行は除外したのと同じ。

- 新しい取引を重く見る：古いデータを捨てずに、test に近い時期の取引を優先できる
- 成約価格情報を重く見る：train では 45%、test では 67% なので、train の構成を test に近づけられる

重みは学習のときだけ付け、CV のスコアは重みなしで計算する。

### 価格を使う特徴量（工程 2）

地区ごとの平均価格（target encoding）のように価格を使う特徴量は、工程 2 で全データから計算してはいけない。工程 2 は fold に分ける前に実行されるので、検証期間の価格が学習に漏れて、CV が実際より良く出る。fold ごとに計算する仕組みが必要なので、取りかかるときにチームで相談して足す。

## 進め方の原則

### 1 つずつ変えて、良ければ main に取り込む

工程どうしには相性があるが、組み合わせを総当たりはしない。main ブランチが常に「今の土台」になる。

```
main（土台）
  └ ブランチでトレンド除去を試す → CV が良くなった → PR でマージ（全員がこの上で実験）
       └ ブランチで場所の特徴量を試す → 良くなった → PR でマージ
            └ ブランチで重み付けを試す → 悪くなった → PR を閉じて記録を残す
```

- 一度に変えるのは 1 つだけ。変える前と後の CV を比べれば、その変更が効いたかが分かる
- 良くなった変更は main に入れる。以降の実験はその上で行うので、相性は「今の土台との相性」として確かめられる。実験の数は試した手の数で済み、掛け算にはならない
- 相性が強く出やすい場面だけ、試し直す

| 場面 | 対処 |
|---|---|
| 上流の工程（目的変数・学習データ）を変えた | 前に採用しなかった手のうち、関係しそうなものだけを試し直す |
| 特徴量が大きく増えた | パラメータを 1 回調整し直す |
| アンサンブル | 違う種類のモデルほど混ぜる効果が大きいので、最後にまとめて試す |

### そのほか

- **4 と 8 がこのコンペの肝**：決定木は、学習期間より高い価格水準を予測できない。価格が上がり続けているので、トレンドの扱い（4 で引いて 8 で戻す、または 8 で補正する）が特徴量より効く可能性がある
- **前の工程から固める**：1〜4 で「何を学習させるか」が固まらないうちに 6・7 をしても、土台が変わるたびにやり直しになる。6・7 は後半に回す
- **0 を先に見る**：特に「四半期ごとの価格推移」と「train と test の違い」は、3・4・8 の方針を決める材料になる
